What a GameMaker game actually is

Undertale ships as data.win — a 63 MB container of chunked, offset-addressed data and BC16 bytecode. No source. No symbols. The port is a from-scratch interpreter for that bytecode plus a loader for the chunk format: GEN8, OPTN, STRG, TXTR, TPAG, SPRT, BGND, ROOM, OBJT, CODE, FONT, SOND, AUDO, AGRP, FUNC, VARI.

The runner executes the game's own VM: stack, instance scope, with(), alarms, collisions, the event ordering, and the whole built-in function surface. When the original game asks for draw_self(), it has to mean exactly what it meant in 2016.

Two screens, one machine

400×240 up top, 320×240 below, 268 MHz ARM11, and a GPU that wants everything power-of-two. Textures get packed into a fragmented per-page atlas with a room manifest so a scene only streams the pages it needs. Draws batch; a page budget caps residency. On the old 3DS the whole atlas cannot be resident — eviction is demand-driven, never eager, because eager flushing is exactly what makes a room seam visibly "reload".

Audio: the DSP is not your PC

Everything is ADPCM through the hardware DSP. Music streams from file in native ADPCM; sound effects live in a packed bank. There are 24 voices total — and GameMaker happily retriggers a text blip faster than the 1.7-second sample can finish, so the pool fills and later sounds are silently dropped. The fix is to steal the oldest non-stream voice when the pool is full, and always ask for a free channel first — getting that order wrong silences every sound in the game.

THE HEAP. The 8 megabyte wall.

This is the one that killed builds. After parsing a 63 MB data.win, an Old 3DS has roughly 8.6 MB of application heap left. The 17.7 MB sound bank cannot be a single app-heap allocation — it goes to the separate linear heap. A failing malloc that calls abort() doesn't show a crash screen; it tears services down mid-frame and the evidence points somewhere absurd, like hidScanInput reading a null shared memory. Every hot path had to learn to fail soft and log instead.

Three bugs that looked like something else

  • The stack. A 3DSX gets a 32 KB main-thread stack. Deep script call chains walked straight off it. Dump showed the stack pointer below the image end, mid-VM. Now 256 KB.
  • The shadowing. The music resolver matched exact filenames, so a raw .ogg sitting beside its converted .bcwav twin fed Vorbis bytes to the CWAV parser forever.
  • The ghosts. 46 music cues — piano notes, the drum kit, the dial-up — exist only embedded inside data.win's AUDO chunk. No file to convert, so they were permanently silent until the preprocessor learned to reach into the chunk.

The pipeline, end to end

Your data.win goes in, and out comes a card-shaped tree:

data.win ─┬─▶ texture atlas (per-page .t3x) + direct assets
          ├─▶ streamed music  → 248 × .bcwav   (incl. embedded-AUDO)
          ├─▶ packed SFX bank → sound_bank.bin (PCM16)
          ├─▶ room manifest · fonts · borders
          └─▶ 3ds/U3DS/  ← copy this to the card

The game's own data.win is never modified — it's parsed at runtime on the console. That's why this page can hand you a converter instead of a download.

03 Build it yourself

devkitARM + libctru. The whole runner builds in under a minute.

git clone https://github.com/RANCH-BLAD/UNDERTALE-ON-3DS
cd UNDERTALE-ON-3DS

# 1. turn YOUR data.win into card assets
./tools/patch.sh /path/to/your/data.win

# 2. or build the runner from source
export DEVKITPRO=/opt/devkitpro
cmake -S . -B build/n3ds -G Ninja \
  -DCMAKE_TOOLCHAIN_FILE=$DEVKITPRO/cmake/3DS.cmake \
  -DPLATFORM=n3ds -DCMAKE_BUILD_TYPE=Release
cmake --build build/n3ds
# => build/n3ds/cinnamon.3dsx

CI does this automatically — see .github/workflows/build.yml.

04 THE LEGAL SLUDGE REPORT

No game assets are distributed here. No data.win, no sprites, no music, no fonts. Not in the repo, not in Releases, not in CI artifacts.

You must own Undertale. The converter reads your copy and generates assets for your console. That's the whole model — it is not a way to get the game.
